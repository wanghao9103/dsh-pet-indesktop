## 一、核心特性

原快速聊天只提交模型请求并展示文字，没有调用宠物动画控制器。
现在发送“跳一下”“转个圈”“往左走几步”“向右移动一下”会直接驱动当前宠物。
跳舞、伸懒腰、小憩也有对应指令，但需要当前角色实际提供对应素材。

只识别完整、明确的单条正向指令；否定、引用、讲故事和多步请求继续走原聊天流程。
动作由本地确定性通道执行，不需要 API Key，也不产生该动作的模型请求。
这是快速聊天的交互能力，未向完整聊天窗或模型回复添加自动执行能力。

## 三、实现要点

- 发送槽在 GUI 线程解析最多 96 字的完整输入，调用宿主面 `perform_chat_action`。
- 动画名按空白归一化匹配，但传给播放器的是素材库原始键；精简包的 `点击回应-开心跃动` 也可用于跳跃。
- 转圈优先使用角色的 360° 动画，缺少可选视频时复用 `GoldenSpinController`；目标仍为发起聊天的那只。
- 位移仍由现有步态曲线和边界规划驱动；指定方向走不了就反馈失败，保留“不移动”设置与拖拽/飞行守卫。
- 只有控制器接受后才显示“开始”；素材缺失、宿主缺失、起播失败等返回明确反馈。
- 所有动作都是一次性；既有自动行为会在动作结束后继续。普通聊天的提供商、代理、记忆与流式链路未调整。

## 四、性能分析

环境：Linux x86_64；测试 Python 3.14 / PySide6 6.11.2；冻结包 Python 3.11.17。

解析测量命令：`/data/chatgpt/问答/.codex/dsh-pet-runtime/bin/python scripts/benchmark_quick_chat_actions.py`
（在源码目录运行）。每种输入 7 批 × 10,000 次，取批均值的中位数。
测量期间有其他测试运行，因此数字是该开发机当时结果，不是空载性能承诺。

| 输入长度/类型 | 中位数，微秒/次 |
|---|---:|
| 3 字动作指令 | 15.140 |
| 11 字带称呼/礼貌语指令 | 21.202 |
| 6 字方向移动 | 22.228 |
| 9 字普通聊天 | 20.135 |
| 3 字否定句 | 18.454 |
| 11 字引用场景 | 14.638 |
| 1500 字超长输入早退 | 0.477 |

最终冻结包原生探针各动作 1 次：发送槽耗时依次 15.608 / 5.191 / 9.635 / 4.286 ms。
跳跃观察到第 1 帧耗时 44.5 ms，旋转观察到非零角度 21.7 ms；左右步态出现超过 2px 的位移约 1046 / 1052 ms，包含既有步态静帧段，不能理解为整段没有动画。

稳态：没有每帧/每 tick 新增工作，只在用户提交消息时解析一次。新增短时字符串、dataclass 和素材名映射，无持久缓存。
显式动作少一次模型网络请求；会话写盘沿用原追加接口。动画可能沿用既有按需读盘、解码线程或 ffmpeg 子进程；旋转复用已有按动作启停的 16ms 定时器，没有新增常驻轮询或线程。
